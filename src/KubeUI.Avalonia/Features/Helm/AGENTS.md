# Helm Feature

- Helm integrations live under `Features/Helm/`; Kubernetes-layer contracts and Helm client operations live in `KubeUI.Kubernetes/Helm/`.
- Use `Helm.NET` for Helm actions; never launch the Helm executable.
- Run synchronous native calls off the UI thread and serialize native Helm calls because the shim and default repository configuration are process-wide.
- Helm navigation owns the `Helm` section with `Repositories`, `Charts`, and `Releases` documents; Helm data is not a Kubernetes `ResourceConfig`.
- Charts uses the shared table/list styling, compact header, item count, repository dropdown sorted by repository name (ordinal-ignore-case), grid-local chart filter, refresh, and an **Install chart** context action. Load cached catalog with `ListCharts`, show one row per qualified chart reference with latest stable version, and ignore prerelease versions in this list. Filter locally by repository and chart name. Do not show a separate status row. Install chart opens a new install editor prefilled with repository, chart, and latest stable version, leaving release name for user input; do not install until the user completes and confirms the form.
- Repository forms must include name, URL, and optional basic-auth credentials. Repository rows support refresh, index update, add, edit, and delete.
- Release rows support namespace-scoped or all-namespace listing, install, upgrade, status, values, history, rollback to a chosen revision, uninstall, and chart template preview.
- Refresh release data on every view load, including reattachment of an existing document, through a lifecycle behavior. Fetch all namespaces and apply namespace selection as a local table filter; an empty selection means all namespaces.
- Keep Helm UI text in Resources.resx and cover service, navigation, and ViewModel behavior with tests.
- Repository and release list headers follow resource-list layout: minimum height 32, vertical margin 2, left add-square action and item-count label with left margin 2, stretch spacer, right-aligned controls/actions, and bounded wrapping status text. Repository index updates stay in the right action group; do not displace the count.
- Distinguish downloading repository indexes (`ArrowDownload`, including the context menu) from refreshing the displayed repository list (`ArrowSync`).
- Release-list **View values** converts the returned JSON values into YAML using the shared serializer and opens a locked, read-only YAML view in the bottom panel, like resource **View YAML**, not a document tab or toolbar status text. Reuse the same TextMate YAML highlighting. Preserve nested mappings, sequences, scalar types, nulls, and quoted strings. Include release name and namespace in the title; retain errors in the release view status.
- Install/upgrade forms edit YAML mappings, not JSON. Upgrade initialization asynchronously loads installed user values from the release namespace, blocks editing/submission during loading, and blocks submission after a values-fetch failure. Save and template preview must parse the edited YAML with duplicate-key checking and retain nested values and scalar types.
- Release editors must scroll within constrained docking panels: keep the whole form in a vertical scroll viewer and bound the YAML editor height so its own scroll viewport remains finite for long values. Bottom actions must remain reachable.
- Reuse `YamlSyntaxHighlightingBehavior` for the same theme-aware TextMate YAML colors as the resource viewer. Keep editor/model updates bidirectional.
- Helm.NET alpha.9 provides separate `ChartName`/`ChartVersion`, repository search with version enumeration, versioned template/install/upgrade, stored-release manifest retrieval, and native all-namespace listing. The Kubernetes service maps chart catalog listing/search to `SearchRepo` over cached indexes and maps release manifest retrieval to `GetManifest`. Resolve an upgrade chart using exact chart-name matches from the cached catalog, deduplicated by reference across versions. Never use `HelmRelease.Chart` as a reference or guess between multiple repositories; request a manual reference when no unique match exists. Keep installed-release visualization live, not based on stored/template manifests.
- Pass selected chart version to install and upgrade APIs, as well as versioned preview. Manual or OCI references can omit version to use Helm's default resolution. Stored-manifest retrieval returns saved release output and does not accept edited values; it must not replace editor template preview.
- Install and upgrade forms display available versions for the selected repository reference, deduplicated, with installed `ChartVersion` selected initially on upgrades. Retain the installed version even when missing from repository indexes. Versioned preview, install, and upgrade pass selection and edited YAML values to Helm.NET. A blank version uses Helm default resolution, including for manual or OCI references.
- Release editors offer linked repository and chart dropdowns alongside chart versions. Load configured repositories and cached catalogs with `ListCharts`; filter charts by repository/name and versions by qualified reference; clear stale selections when parents change. Keep manual/OCI references available and surface index/catalog failures. Only carry the installed version across selections of the installed chart, not unrelated charts.
- Keep repository, chart, and version selectors full-width and aligned with the form input column, with separate labels. Upgrade initialization must select the unique repository/chart match in the actual controls, whether metadata came from the listing or Status. `ListCharts(repositoryName)` reads local cached indexes without refreshing them and does not enumerate OCI registries.
- Test editing releases with no configured repositories, no exact chart match, and unavailable repository indexes, both with listing metadata and Status-loaded metadata. Preserve loaded YAML and the installed version on discovery failures, never guess a chart reference, and allow explicit manual/OCI references for versioned preview. Keep errors visible and verify blocked upgrades never reach Helm.
- `GetManifest` returns the manifest stored for a release revision; it does not render chart templates. Use versioned `Template` with the original chart reference for dependency-complete rendering and edited-value previews.

## Helm release visualization preview

- Release-list **Visualize** constructs a generic `VisualizationScope` with the release namespace, localized release description, readonly namespace/link controls, and an annotation selector requiring both `meta.helm.sh/release-name` and `meta.helm.sh/release-namespace`. Keep Helm-specific keys and display text in this feature, not the visualization ViewModel. Initialize local namespace selection without changing cluster selection, and use shared graph projection/incremental processing for live updates. Include relationship ancestors and owned descendants, but do not expand Flux GitOps descendants of selected resources.
- Only the new/edit release editor uses **Preview in Visualization** to render a chart with Helm.NET template and values into an isolated read-only preview. Release-list visualization must not render a chart or fetch values; `HelmRelease.Chart` is display text, not a chart reference.
- Parse the rendered multi-document manifest into Kubernetes resource objects and use the existing `IResourceRelationshipBuilder`/visualization graph pipeline to show relationships among the rendered resources.
- Keep preview resources isolated from the live cluster resource store and informer feed: preview must not apply, seed, or mutate Kubernetes resources. Preserve visualization filters and make unresolved references to resources outside the rendered release visible.
- Test manifest parsing, preview-resource isolation, relationship construction, editor/list preview actions, and error handling for Helm rendering or invalid manifests.
