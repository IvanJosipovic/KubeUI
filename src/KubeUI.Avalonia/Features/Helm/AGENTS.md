# Helm Feature

- Helm integrations live under `Features/Helm/`; Kubernetes-layer contracts and Helm client operations live in `KubeUI.Kubernetes/Helm/`.
- Use `Helm.NET` for Helm actions; never launch the Helm executable.
- Run synchronous native calls off the UI thread and serialize native Helm calls because the shim and default repository configuration are process-wide.
- Helm navigation owns the `Helm` section with `Repositories`, `Charts`, and `Releases` documents placed after custom resources via `NavigationSections.AfterCustomResourcesOrder`; Helm data is not a Kubernetes `ResourceConfig`.
- Charts uses the shared table/list styling, compact header, item count, repository dropdown sorted by repository name (ordinal-ignore-case), grid-local chart filter, refresh, and an **Install chart** context action. Load cached catalog with `ListCharts`, show one row per qualified chart reference with latest stable version, and ignore prerelease versions in this list. Filter locally by repository and chart name. Do not show a separate status row. Install chart opens a new install editor prefilled with repository, chart, latest stable version, and the selected cluster namespace (falling back to `default`), leaving release name for user input; do not install until the user completes and confirms the form.
- Repository forms must include name, URL, and optional basic-auth credentials. Repository rows support add, edit, and delete; the list header supports refresh and one index download covering all configured repositories. Do not add a per-row index-update action. Repository **View charts** opens or focuses the cluster chart document through `IHelmDocumentOpener` and applies the repository filter; list view models must not resolve navigation services or compose document ids themselves.
- Chart documents own their document id and refresh when the view loads, so opening an already-open chart document only reapplies the requested repository filter.
- Repository and release editors must not depend on their list view model. Open charts through `IHelmDocumentOpener` (which owns tab creation), and report saved changes through the singleton `IHelmListNotifier`; open lists subscribe and refresh themselves. Never reach across features to construct another feature's list view model.
- Saving a repository form that changed nothing must skip the Helm `RepoAdd` call, because re-adding without credentials silently drops stored basic auth. The form warns that Helm does not return saved credentials; unchanged edits are still acknowledged as successful.
- Release rows support namespace-scoped or all-namespace listing, install, upgrade, status, values, rollback to a chosen revision, uninstall, and chart template preview. Rollback dialog includes revision history. Format the Updated column with the same pretty age text as resource Age cells.
- Refresh release data on every view load, including reattachment of an existing document, through a lifecycle behavior. Fetch all namespaces and apply namespace selection as a local table filter; an empty selection means all namespaces.
- Keep Helm UI text in Resources.resx and cover service, navigation, and ViewModel behavior with tests.
- Repository and release list headers follow resource-list layout: minimum height 32, vertical margin 2, left add-square action and item-count label with left margin 2, stretch spacer, right-aligned controls/actions, and bounded wrapping status text. Repository index updates stay in the right action group; do not displace the count.
- Top-bar status messages must remain clear and concise (at most two words); log detailed exception text instead of displaying it in the header.
- Distinguish downloading repository indexes (`ArrowDownload`, header action) from refreshing the displayed repository list (`ArrowSync`).
- Release-list **View values** converts the returned JSON values into YAML using the shared serializer and opens a locked, read-only YAML view in the bottom panel, like resource **View YAML**, not a document tab or toolbar status text. Reuse the same TextMate YAML highlighting. Preserve nested mappings, sequences, scalar types, nulls, and quoted strings. Include release name and namespace in the title; retain errors in the release view status.
- Install/upgrade forms edit YAML mappings, not JSON. Upgrade initialization asynchronously loads installed user values from the release namespace, blocks editing/submission during loading, and blocks submission after a values-fetch failure. Save and template preview must resolve anchors and merge keys, reject duplicate explicit keys, and retain nested values and scalar types. Validate duplicates on the raw `YamlStream` tree before deserializing with the merging parser: the merge expansion happens before the deserializer's duplicate check, which would otherwise reject legitimate explicit overrides of merged keys.
- Release editors must scroll within constrained docking panels: keep the whole form in a vertical scroll viewer and bound the YAML editor height so its own scroll viewport remains finite for long values. Bottom actions must remain reachable.
- Place Create namespace directly below Namespace, and Timeout directly above Values (YAML).
- Replacing YAML with asynchronously loaded chart defaults must preserve the release form and YAML editor scroll positions and caret; loading defaults must not move either viewport.
- Reuse `YamlSyntaxHighlightingBehavior` for the same theme-aware TextMate YAML colors as the resource viewer. Keep editor/model updates bidirectional.
- Helm values YAML editors use the shared `YamlFoldingBehavior` for nested YAML folding; keep folding and theme-aware syntax highlighting enabled together.
- Match the resource YAML editor's shared font weight, line numbers, scrollbars, default word-wrap state, and `TextEditorOptions`; retain release-specific loading and bounded-height behavior.
- Helm.NET alpha.10 provides separate `ChartName`/`ChartVersion`, versioned template/install/upgrade, stored-release manifest retrieval, and native all-namespace listing. `HelmRelease.Revision` is an `int` and `HelmRelease.Updated` is a `DateTimeOffset`; format the Updated column with the pretty age helper and format timestamps in status/history text as UTC ISO-8601. The Kubernetes service maps chart catalog listing to a single `SearchRepo` call over cached indexes and maps release manifest retrieval to `GetManifest`; do not expose a separate keyword chart search. Resolve an upgrade chart using exact chart-name matches from the cached catalog, deduplicated by reference across versions. Never use `HelmRelease.Chart` as a reference or guess between multiple repositories; request a manual reference when no unique match exists. Keep installed-release visualization live, not based on stored/template manifests.
- Pass selected chart version to install and upgrade APIs, as well as versioned preview. Manual or OCI references can omit version to use Helm's default resolution. Stored-manifest retrieval returns saved release output and does not accept edited values; it must not replace editor template preview.
- Install and upgrade forms display available versions for the selected repository reference, deduplicated, with installed `ChartVersion` selected initially on upgrades. Retain the installed version even when missing from repository indexes. Versioned preview, install, and upgrade pass selection and edited YAML values to Helm.NET. A blank version uses Helm default resolution, including for manual or OCI references.
- Repository-mode install and upgrade require an explicit chart-version selection; do not show a version placeholder or load chart defaults until a version is selected. Manual and OCI references may still omit version.
- New release editors load selected chart/version default YAML values from Helm.NET. Debounce OCI chart-reference/version text changes, cancel stale loads, and never overwrite values the user edited while a load was pending.
- New release values editor starts blank (empty YAML); blank YAML means empty mapping. Do not display JSON `{}` as the editor's default.
- Release editor validation and operation errors use Avalonia's native field validation and appear beside the responsible field; do not show a bottom-of-form error summary.
- Release editors offer a Repository/OCI radio choice. Repository mode shows repository, chart, and chart-version dropdowns populated from configured repositories and cached `ListCharts` catalogs; OCI mode shows user-entered chart-reference and chart-version text boxes. Do not add a separate chart-search row. Filter repository versions by qualified reference and clear stale selections when parents change. Surface index/catalog failures. Only carry the installed version across selections of the installed chart, not unrelated charts.
- Keep repository, chart, and version selectors full-width and aligned with the form input column, with separate labels. Upgrade initialization must select the unique repository/chart match in the actual controls, whether metadata came from the listing or Status. `ListCharts(repositoryName)` reads local cached indexes without refreshing them and does not enumerate OCI registries.
- Test editing releases with no configured repositories, no exact chart match, and unavailable repository indexes, both with listing metadata and Status-loaded metadata. Preserve loaded YAML and the installed version on discovery failures, never guess a chart reference, and allow explicit manual/OCI references for versioned preview. Keep errors visible and verify blocked upgrades never reach Helm.
- `GetManifest` returns the manifest stored for a release revision; it does not render chart templates. Use versioned `Template` with the original chart reference for dependency-complete rendering and edited-value previews.

## Helm release visualization preview

- Release-list **Visualize** constructs a generic `VisualizationScope` with the release namespace, localized release description, readonly namespace/link controls, and an annotation selector requiring both `meta.helm.sh/release-name` and `meta.helm.sh/release-namespace`. Keep Helm-specific keys and display text in this feature, not the visualization ViewModel. Initialize local namespace selection without changing cluster selection, and use shared graph projection/incremental processing for live updates. Include relationship ancestors and owned descendants, but do not expand Flux GitOps descendants of selected resources.
- Only the new/edit release editor uses **Preview in Visualization** to render a chart with Helm.NET template and values into an isolated read-only preview. Release-list visualization must not render a chart or fetch values; `HelmRelease.Chart` is display text, not a chart reference.
- Helm rendered-preview resource context menus expose only **View** and **View YAML**; suppress visualization, delete, and custom mutation actions for preview nodes.
- Parse the rendered multi-document manifest into Kubernetes resource objects and use the existing `IResourceRelationshipBuilder`/visualization graph pipeline to show relationships among the rendered resources.
- Keep preview resources isolated from the live cluster resource store and informer feed: preview must not apply, seed, or mutate Kubernetes resources. Preserve visualization filters and make unresolved references to resources outside the rendered release visible.
- Test manifest parsing, preview-resource isolation, relationship construction, editor/list preview actions, and error handling for Helm rendering or invalid manifests.
